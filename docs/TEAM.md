# 团队账号与项目权限

本机版默认使用 `AFDS_MODE=local`，操作者映射为保留的本机主体。团队版设置 `AFDS_MODE=team`，使用服务端会话与项目成员关系。

## 建立账号

在后端运行环境执行以下交互式命令，密码通过隐藏输入读取。

```sh
python -m app.admin create-user <username> --admin
python -m app.admin create-user <username> --display-name <name>
```

用户名使用 3–64 个 ASCII 字母、数字、点、下划线或连字符。密码支持 12–1024 个字符，首尾空格保留。密码采用 Argon2id，数据库仅保存随机会话令牌和 CSRF 令牌的摘要。

管理员在全局设置中维护连接。项目创建者成为所有者，通过项目顶部的“项目成员”按用户名添加成员。管理员查看私有项目同样需要项目成员资格。

## 项目角色

| 角色 | 可执行动作 |
| --- | --- |
| 所有者 owner | 查看、下载、编辑、生成、审片、批准脚本、管理成员和预算 |
| 编辑者 editor | 查看、下载、编辑、生成、审片、批准脚本 |
| 审片者 reviewer | 查看、下载、审片和选片批准 |
| 查看者 viewer | 查看和下载 |

最后一名所有者受到并发保护。用户可以取消本人有权限提交的任务。所有者和编辑者可以管理项目任务，重新执行会记录当前执行操作者并保留最初创建者。

移除成员后，后续请求立即重新检查权限。Worker 启动排队任务前重新检查当前执行权限。已提交远端的任务继续通过任务详情处理取消、结果未知和计费对账。

## 登录与部署

会话默认有效 8 小时。登录轮换会话，注销使服务端会话失效。写请求使用 CSRF 令牌，前端自动附带同源 API 请求。Cookie 默认启用 HttpOnly、Secure 和 SameSite=Lax，生产环境通过同源 HTTPS 提供服务。登录限制按账号与请求来源的摘要执行。

`AFDS_SECURE_COOKIES=false` 仅供显式配置的本机 HTTP 演练使用。团队模式的 API 文档、运行诊断及全局连接管理要求管理员身份。

## 旧项目迁移

完成数据库备份与迁移后，明确指定接收旧本机项目的账号。

```sh
python -m app.admin claim-local-projects --owner <username>
```

该命令分配本机主体拥有或缺少团队归属的项目。已有团队所有者的项目保留现有归属。工程 ZIP 用于创作内容移植，恢复后的新项目归当前操作者所有。账号、密码与会话留在部署数据库。

## 制作技能

团队导入的技能包及源码按项目授权，内置技能提供公共只读定义。团队外部脚本必须经过源码预览、固定容器策略和逐次明确批准。脚本运行使用隔离 Linux 容器，策略与镜像身份记录在任务中。镜像构建与运行条件参见沙箱说明。
